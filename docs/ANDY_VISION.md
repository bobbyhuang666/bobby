# Andy 引擎发展愿景 v2

> 不是一个心理学模拟库，是虚拟生命的操作系统。

---

## 核心定位

Andy 是一个多智能体心理学引擎，目标是成为虚拟世界和开放世界游戏的底层架构。

它解决的核心问题：**让 NPC 不只是"会说话"，而是"在活着"。**

当前游戏行业 NPC 的两条路线都有硬伤：

- **行为树 + 脚本对话**：NPC 是木偶，行为可预测，对话是死的
- **纯 LLM 驱动**：NPC 能聊天但没有"生活"，行为不可控，成本高

Andy 填补中间那一层——**NPC 的内心世界**。心理引擎驱动行为和内心状态，LLM 只负责"说出来"。

```
行为树 + LLM：  给了 NPC 一张嘴
Andy + LLM：    给了 NPC 一颗心
```

---

## Andy vs LLM 的分工

Andy 的边界要清晰：

| Andy 负责（确定性、可复现） | LLM 负责（创造性、语言表达） |
|---|---|
| NPC 在哪、做什么 | NPC 说出来的话 |
| NPC 的情绪状态 | 情绪的具体表达方式 |
| NPC 记住了什么 | 如何用语言回忆这件事 |
| NPC 跟谁关系好 | 关系好到什么程度的对话风格 |
| NPC 的需求和欲望 | 如何表达自己的需求 |
| 世界的因果逻辑 | 细节的丰富和润色 |

**Andy 是骨架，LLM 是血肉。骨架决定了这个人是谁，血肉决定了这个人长什么样。**

## 许可证策略（必须先想清楚）

当前 CC BY-NC-SA 4.0 禁止商业使用。这和"游戏底层架构"的目标矛盾。

**双轨制方案：**

| 使用场景 | 许可证 | 说明 |
|----------|--------|------|
| 学术研究、个人学习、非商业项目 | CC BY-NC-SA 4.0 | 免费，保持现状 |
| 商业产品（游戏、App、平台） | 商业授权 | 付费，单独谈判 |

开源版本永远免费且非商业。商业版本提供额外支持、性能优化、SLA。

这个模式在开源领域很成熟（MySQL、Redis、MongoDB 都是这么做的）。

## 四个方向

### 方向一：学术论文（最高优先级）

**为什么最先做：**

- Andy 已经有学术基础：14 个参考文献、1084 个测试、18 个模块
- 论文成本低（1-2 个月），但回报高：建立学术信誉 + 吸引研究者 + 自然传播
- 与非商业许可完美兼容
- Generative Agents 论文引爆了整个领域，Andy 的心理学模型比它更深

**论文框架：**

```
标题：Andy: A Psychology-Driven Multi-Agent Social Simulation Engine

摘要：
我们提出 Andy，一个基于心理学理论的多智能体社会模拟引擎。
与基于 LLM 的方法不同，Andy 使用计算心理学模型驱动角色行为：
- 30 维情绪系统（Cowen & Keltner 2017）
- ACT-R 记忆模型（Anderson 2007）+ 5 通路检索
- Scherer 认知评价（8 维度）
- Gross 情绪调节过程模型
- Maslow 需求层级
- Dunbar 社交图谱 + 三元闭合

我们在 1084 个单元测试和行为验证测试上验证了系统，
并通过一个 AI 陪伴应用（Bobby）展示了实际部署效果。

对比 Generative Agents（Stanford 2023）：
- 情绪模型深度：30 维 vs 仅 valence
- 记忆模型：ACT-R 5 通路 vs 简单重要性排序
- 成本：纯 CPU vs 每次 tick 调用 LLM
- 可复现性：确定性 vs LLM 随机性
```

**目标会议/期刊：**
- AAMAS（Autonomous Agents and Multi-Agent Systems）
- AIIDE（Artificial Intelligence and Interactive Digital Entertainment）
- CHI（如果强调人机交互角度）
- 或 arXiv 预印本先发布

### 方向二：可视化 Demo（传播力最强）

**为什么第二做：**

Generative Agents 的 Smallville demo 震撼了全世界，但他们的心理学模型其实很简单。你已经有了更深的模型——缺的就是那张"脸"。一个 5 分钟的可视化视频比任何文档都有传播力。

**关键动作：**

1. **Web 端 2D 小镇可视化**
   - 技术：Canvas / PixiJS / Three.js（纯前端，不需要游戏引擎）
   - 地图：小镇区域布局（面包店、酒馆、广场、住宅区……对应 RegionGrid）
   - 角色：每个 Agent 的位置、头像、当前状态
   - 时间：加速播放，一天浓缩成 5 分钟
   - 交互：点击角色查看情绪面板、记忆列表、社交关系图

2. **实时信息流**
   - 内心独白以气泡形式飘出（心智游移事件）
   - 角色相遇时显示交互内容
   - 情绪以颜色变化可视化
   - 社交关系以连线粗细变化可视化

3. **Demo 故事：三个角色的一天**
   - 面包师老王（ESFJ）：6 点起床烤面包，跟老顾客聊天，晚上跟老婆吃饭
   - 流浪诗人（INFP）：睡到中午，在酒馆弹吉他，暗恋面包店的女儿，晚上写诗
   - 卫兵（ISTJ）：按时巡逻，最近压力大睡眠不足，跟诗人是老同学但关系疏远了

4. **录制视频传播**
   - 5 分钟视频，展示多角色自主生活
   - 投放：Twitter/X、YouTube、B 站、学术社区
   - 标题："每个 NPC 都有自己的心理学引擎——Andy 多智能体模拟"

### 方向三：虚拟社区（低成本高回报）

**为什么这个方向被低估：**

不是游戏 NPC，而是 Web 端的虚拟生活空间。比游戏引擎集成简单 10 倍，跟 Bobby 方向一脉相承。

**产品形态：**

| 产品 | 描述 | 技术栈 |
|------|------|--------|
| 虚拟自习室 | AI 同学在旁边学习，你也会被氛围影响 | Web + Andy + Socket.io |
| 虚拟咖啡店 | AI 角色在聊天，你旁听，氛围感拉满 | Web + Andy + LLM |
| 虚拟宿舍 | AI 室友有自己的生活节奏 | Web + Andy + Bobby 模式 |
| 虚拟城市 | 2D 小镇，居民自主生活，玩家可以跟任何人对话 | Web + Andy + LLM |

**为什么比游戏引擎更现实：**
- Web 端没有技术栈障碍（Andy 本身就是 Node.js）
- 不需要处理游戏引擎的渲染、物理、动画
- 可以快速迭代，快速验证
- 用户不需要安装任何东西

**Bobby 其实就是"虚拟单间"的原型。** 往这个方向扩展是自然的。

### 方向四：游戏引擎集成（长期目标）

**现实：这比想象的难 10 倍。**

Andy 是 Node.js 运行时。Unity 用 C#，Unreal 用 C++，Godot 用 GDScript。

| 集成方案 | 可行性 | 问题 |
|----------|--------|------|
| HTTP/WebSocket 桥接 | ✅ 可行 | 延迟（NPC 状态查询需要毫秒级） |
| WASM 编译 | ⚠️ 不成熟 | Node.js → WASM 工具链不完善 |
| 原生重写 | ⚠️ 工作量大 | 核心逻辑用 C#/C++ 重写 |
| Godot（开源） | ✅ 最现实 | GDScript 可通过 WebSocket 对接 |

**如果走游戏引擎方向，建议先做 Godot：**
- Godot 开源免费，社区活跃
- GDScript 可以通过 WebSocket 调用 Andy 服务
- 2D 游戏场景足够验证概念
- 不需要处理 Unreal/Unity 的商业授权问题

**技术前提：事件驱动架构**

当前 Andy 是 tick 驱动（固定间隔推进）。游戏场景需要事件驱动——玩家做了某件事，NPC 立即响应。

需要把 Simulator 从同步循环改为异步事件总线：
```javascript
// 当前：tick 驱动
world.tick(); // 推进一次，所有 Agent 同时思考

// 未来：事件驱动
world.emit('player_action', { agentId: 'baker', action: 'give_gift', item: 'bread' });
// → baker 立即评价这个事件 → 情绪变化 → 状态可能变化 → 通知游戏引擎
```

这是游戏集成的前提，但改动很大，不急于现在做。

## 修订后的路线图

```
阶段 1（现在）：Bobby 持续运营
  └── Bobby 是 Andy 的第一个应用，验证"Andy + LLM"模式
  └── 收集用户反馈，打磨核心模块
  └── 同时思考许可证策略

阶段 2（1-2 个月）：学术论文
  └── 整理 Andy 技术贡献，写论文
  └── arXiv 预印本 + 投会议
  └── 建立学术信誉，吸引研究者关注

阶段 3（2-3 个月）：可视化 Demo
  └── Web 端 2D 小镇，3-5 个角色
  └── 录制 5 分钟视频传播
  └── Andy 的"名片"——让所有人看到

阶段 4（1 个月）：SDK + npm 发布
  └── 清理 API，写文档
  └── 预设人格模板、世界模板
  └── 有了论文和 Demo 后，SDK 才有人用

阶段 5（评估后决定）：虚拟社区 或 游戏引擎
  └── 如果社区反馈偏向"氛围感" → 虚拟社区产品
  └── 如果社区反馈偏向"游戏 NPC" → Godot 插件原型
  └── 两条路可以并行，但资源有限时选一条先走

长期：规模化
  └── 事件驱动架构（游戏集成前提）
  └── 空间分区优化
  └── 多线程 / Worker 支持
  └── 100+ Agent 性能基准
```

## 最后

Andy 不是在跟 LLM 竞争，是在给 LLM 提供它缺少的东西——**一颗有记忆、有情绪、有社交关系、会自主行动的心。**

LLM 可以让 NPC 说话。
Andy 可以让 NPC 活着。

两者结合，才是虚拟生命的完整形态。
